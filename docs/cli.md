# Текстовый CLI поверх UART

Человекочитаемый и одновременно машинно-парсимый протокол управления и
телеметрии. Используется для отладки в терминале и как транспорт команд для
GUI на PyQt/PySide6.

Первоисточник по грамматике — заголовок [firmware/src/middleware/shell/inc/shell.h](../firmware/src/middleware/shell/inc/shell.h).
Реализация диспетчера — [shell.c](../firmware/src/middleware/shell/src/shell.c).

> CLI **не заменяет** бинарный TLV-протокол из [protocol.md](protocol.md). Текстовый
> канал удобен для интерактивной диагностики и быстрой интеграции GUI; бинарный
> остаётся для трактов, где важна плотность и гарантии CRC. Транспорт у обоих
> один и тот же — USART2, 115200 8N1.

## 1. Канал

| Параметр    | Значение     |
|-------------|--------------|
| Интерфейс   | USART2 (PA2/PA3, AF7) |
| Скорость    | 115200 baud  |
| Формат      | 8N1, без управления потоком |
| TX путь     | DMA1 Stream6 Ch4, неблокирующая отправка из задачи |
| RX путь     | RXNE-IRQ → SPSC ring 256 байт → `task_protocol` |
| Пины драйвера   | STEP/DIR/EN = PA8/PA9/PA10. PA1 = Hall AH49E (ADC1_IN1), PA0 = STEP self-probe (ADC2_IN0). См. [pinout.md](pinout.md) |

## 2. Формат строк

- **Разделитель строк на входе:** `\r`, `\n` или `\r\n`. Пустые строки игнорируются.
- **Разделитель строк на выходе:** всегда `\r\n` (удобно для PuTTY и для
  `QSerialPort::readLine`).
- **Максимальная длина команды:** 127 символов; всё длиннее → `-ERR line-too-long`.
- **Кодировка:** ASCII. Регистр команды и подкоманды не важен (нормализуется
  в верхний); числовые аргументы — десятичные.

Каждая исходящая строка от MCU начинается с **типового префикса**, по которому
парсер хоста решает, как с ней работать:

| Префикс | Тип строки                          | Пример                         |
|---------|-------------------------------------|--------------------------------|
| `+OK`   | успешный ответ на команду           | `+OK PING uptime=12345`        |
| `-ERR`  | ошибка выполнения команды           | `-ERR MOVE bad-speed`          |
| `$M,`   | сэмпл стрима мотора                 | `$M, 12345, 1000, 520, 2000, 1, 0` |
| `$T18,` | сэмпл DS18B20                       | `$T18, 12345, 26.6`            |
| `$H,`   | сэмпл AH49E                         | `$H, 12345, 2050, 2`           |
| `$P,`   | сэмпл self-probe (ADC2/PA0)         | `$P, 12345, 1000, 2050`        |
| `$D,`   | строка raw-дампа (PROBE DUMP)       | `$D, 0, 0a30b40d4f...`         |
| `!`     | асинхронное событие                 | `!STATE MOVING`                |
| `#`     | комментарий/баннер (можно игнор.)   | `# stepper_control 0.1.0 ready`|

CSV-поля разделены `, ` (запятая + пробел) — для читабельности в терминале.
Парсер на хосте: `[s.strip() for s in line[3:].split(",")]` (или просто
`.split(", ")`).

Парсер на хосте читает построчно и диспетчеризует по первому символу.
Любая нераспознанная строка — мусор в линии или сообщение более новой версии
прошивки; правильное поведение хоста — залогировать и пропустить.

## 3. Унифицированная модель «сенсор/актуатор»

Каждый поточный сенсор и мотор-телеметрия говорят одной и той же четвёркой
verb'ов:

| Verb     | Что делает                                            |
|----------|-------------------------------------------------------|
| `ON`     | Запустить публикацию стрима                           |
| `OFF`    | Остановить публикацию                                 |
| `RATE`   | Задать частоту публикации в Hz                        |
| `READ`   | Разовое чтение, ответ строкой `+OK <PREFIX> ...`      |

Под каждый сенсор есть свой префикс стрима и собственный диапазон допустимых
частот:

| Подсистема | Verb-команда                                          | Стрим      | Диапазон Hz |
|------------|-------------------------------------------------------|------------|-------------|
| Мотор      | `MOTOR ON\|OFF\|RATE <hz>\|READ\|ZERO`                 | `$M`       | 1 … 50      |
| DS18B20    | `TEMP ON\|OFF\|RATE <hz>\|READ\|CONFIG`                | `$T18`     | 1 … 1       |
| AH49E      | `HALL ON\|OFF\|RATE <hz>\|READ\|ZERO\|ZEROCLR`         | `$H`       | 1 … 100     |
| STEP probe | `PROBE ON\|OFF\|RATE <hz>\|READ\|DUMP`                 | `$P`, `$D` | 1 … 50      |

> Для DS18B20 верхняя граница 1 Hz обусловлена `tCONV_max ≈ 750 мс`
> 12-битной конвертации — быстрее физически нельзя. Для дробных частот
> (например, «один раз в 5 секунд») потребуется отдельный механизм; пока
> допустимо только целое 1 Hz.

Дополнительные подкоманды поверх «четвёрки»:

| Verb            | Что делает                                              |
|-----------------|---------------------------------------------------------|
| `HALL ZERO`     | Записать текущее усреднённое значение как «ноль» (B=0). До этого `centered` отсчитывается от теоретической середины 2048. |
| `HALL ZEROCLR`  | Сбросить калибровку.                                    |
| `MOTOR ZERO`    | Прервать движение и обнулить `position` (новая система координат). |
| `PROBE DUMP`    | Снять 4096-сэмпловый снимок ring-буфера ADC2, выдать в `$D`-строки. См. § 6.5. |

## 4. Команды управления мотором

`MOTOR` — это **только телеметрия**. Реальное управление выполняется
отдельными командами:

| Команда                              | Ответ при успехе                          | Возможные `-ERR`                      |
|--------------------------------------|-------------------------------------------|---------------------------------------|
| `MOVE <steps> <speed_sps>`           | `+OK MOVE steps=<s> speed=<v>`, далее `!STATE MOVING` и при завершении `!DONE MOVE` + `!STATE IDLE` | `bad-number`, `bad-speed`, `bad-steps`, `busy`, `not-ready`, `fault` |
| `MOVETO <pos>`                       | (`-ERR MOVETO not-implemented`)           | `not-implemented` (TBD)               |
| `STOP`                               | `+OK STOP`, `!STATE IDLE` если был MOVING | —                                     |
| `HOME`                               | (`-ERR HOME not-implemented`)             | `not-implemented` (TBD)               |
| `EN ON\|OFF`                         | `+OK EN ON` / `+OK EN OFF`                | `bad-arg`                             |
| `DIR FRW\|BCK`                       | `+OK DIR FRW` / `+OK DIR BCK`             | `bad-arg`                             |

`EN` и `DIR` идут через `motor_service`, но в итоге переключают GPIO
**PA10** (active-LOW) и **PA9** соответственно — нужно для bring-up'а
внешнего драйвера. В нормальной работе профилировщик движения будет
выставлять их сам.

`MOVE` уже работает на постоянной скорости: `motor_service_move(steps, speed)`
запускает PWM на TIM1_CH1, отсчитывает шаги в ISR, при завершении эмитит
`!DONE MOVE` и переводит state-машину обратно в `IDLE` (см.
[motor.md](motor.md), [tasks.md](tasks.md)). Профиль скорости (трапеция/S-curve)
ещё не реализован — аргумент `speed` действует на всё движение целиком.

`MOVETO` и `HOME` — stub'ы (`-ERR <CMD> not-implemented`); ждут абсолютной
системы координат и поиска нуля по концевику или Hall-индексу.

## 5. Системные команды

| Команда                              | Ответ при успехе                          |
|--------------------------------------|-------------------------------------------|
| `PING`                               | `+OK PING uptime=<ms>`                    |
| `VER`                                | `+OK VER <maj>.<min>.<patch>`             |
| `STATE`                              | `+OK STATE BOOT\|IDLE\|MOVING\|FAULT`     |
| `HELP`                               | многострочный `+OK HELP …` + `# …`        |
| `RESET`                              | `+OK RESET`, далее MCU перезагружается    |

## 6. Стримы телеметрии

### 6.1. Мотор — `$M,...`

Включается `MOTOR ON`. Период `MOTOR RATE <hz>` (1..50 Гц, дефолт 10).

```
$M, <ts_ms>, <pos>, <speed_sps>, <target>, <en>, <dir>\r\n
```

| Поле        | Тип      | Семантика                                |
|-------------|----------|------------------------------------------|
| `ts_ms`     | `uint32` | uptime, миллисекунды                     |
| `pos`       | `int32`  | текущее положение в шагах (счётчик `motor_service`, обнуляется `MOTOR ZERO`) |
| `speed_sps` | `uint32` | заданная скорость текущего движения, шагов/с (0 если IDLE)         |
| `target`    | `int32`  | целевая позиция текущего движения (совпадает с `pos`, если IDLE)   |
| `en`        | `0\|1`   | состояние линии EN (1 = драйвер активен) |
| `dir`       | `0\|1`   | 0 = FRW (по часовой), 1 = BCK (против)   |

### 6.2. DS18B20 — `$T18,...`

Включается `TEMP ON`. Период `TEMP RATE <hz>` (на DS18B20 — 1 Hz).

> `TEMP CONFIG` отдельно — разовая прошивка EEPROM датчика в 12-бит. Нужна,
> только если конкретный чип когда-то побывал в другом проекте и там ему
> записали 9/10/11-бит (заводское 12-бит хранится в той же EEPROM и не
> восстанавливается само). Подробности — `docs/ds18b20.md` § «Прошивка
> разрешения».

```
$T18, <ts_ms>, <temp_c>\r\n
```

| Поле       | Тип       | Семантика                                       |
|------------|-----------|-------------------------------------------------|
| `ts_ms`    | `uint32`  | uptime в момент окончания чтения scratchpad'а   |
| `temp_c`   | `decimal` | температура; диапазон −55.0 … +125.0            |

### 6.3. AH49E — `$H,...`

Включается `HALL ON`. Период `HALL RATE <hz>` (1..100 Гц, дефолт 10).

```
$H, <ts_ms>, <raw>, <centered>\r\n
```

| Поле        | Тип       | Семантика                                                     |
|-------------|-----------|---------------------------------------------------------------|
| `ts_ms`     | `uint32`  | uptime                                                        |
| `raw`       | `uint16`  | 0..4095, среднее по 16 сэмплам ring-буфера ADC1               |
| `centered`  | `int16`   | `raw - zero_offset`. До `HALL ZERO` отсчёт от 2048.           |

### 6.4. ADC2/PA0 self-probe — `$P,...`

Включается `PROBE ON`. По дефолту используется как self-test STEP-сигнала
через перемычку PA8→PA0; в общем случае — это просто непрерывное
сэмплирование PA0 на ADC2/DMA. Подробнее — [docs/probe.md](probe.md).

```
$P, <ts_ms>, <freq_hz>, <adc>\r\n
```

| Поле       | Тип       | Семантика                                                     |
|------------|-----------|---------------------------------------------------------------|
| `ts_ms`    | `uint32`  | uptime                                                        |
| `freq_hz`  | `uint32`  | оценка частоты по числу пересечений порога 2048 в окне 7.8 мс. Для постоянного аналогового сигнала — 0. |
| `adc`      | `uint16`  | среднее по ring-буферу, 0..4095. Для PWM — DC-компонента (≈ duty × 4095). Для аналога — стабильное напряжение в counts. |

### 6.5. Raw-дамп ring-буфера ADC2 — `$D,...`

Запускается командой `PROBE DUMP`. Выгружает 4096 × 12-бит сэмплов из ring-буфера
ADC2 в hex-формате. На время дампа DMA приостановлен → стрим `$P` (если был `ON`)
не публикуется ~1.1 секунду; по окончании DMA перезапускается. Подробности —
[probe.md](probe.md).

```
+OK PROBE DUMP begin samples=<N> sample_hz=<H>
$D, <line_idx>, <hex 128*3>\r\n
$D, <line_idx>, <hex 128*3>\r\n
... (всего N/128 строк)
+OK PROBE DUMP end
```

| Поле          | Тип       | Семантика                                                |
|---------------|-----------|----------------------------------------------------------|
| `line_idx`    | `uint32`  | номер строки 0..(N/128 − 1), идут по порядку без пропусков |
| `hex 128*3`   | строка    | 128 сэмплов, каждый — 3 hex-символа (12-бит, без разделителей) |

Маркеры `+OK PROBE DUMP begin` и `+OK PROBE DUMP end` дают хосту явные
границы — между ними он гарантированно получит ровно `N/128` строк `$D`.

## 7. Ошибки

`-ERR` всегда укладывается в одну строку. Формат:

```
-ERR <COMMAND> <reason-kebab-case>
-ERR <reason-kebab-case>          # для общих ошибок (например, неизвестная команда)
```

Зарезервированные причины:

| Причина             | Когда                                              |
|---------------------|----------------------------------------------------|
| `unknown <CMD>`     | глагол не в таблице команд                         |
| `usage …`           | неверное число аргументов                          |
| `bad-number`        | аргумент не парсится как десятичное целое          |
| `bad-speed`         | `speed` ≤ 0 или > `PROJ_MOTOR_MAX_SPEED_SPS`       |
| `bad-rate`          | rate вне допустимого диапазона для подсистемы (выводится с `min=`/`max=`) |
| `bad-arg`           | подкоманда не распознана (`TEMP/HALL/PROBE/MOTOR/EN/DIR <other>`) |
| `bad-steps`         | `steps == 0` в `MOVE`                              |
| `busy`              | `MOVE` пришёл во время уже идущего движения        |
| `not-ready`         | `MOVE` до того, как `task_motor` зарегистрировался как owner step_pwm ISR |
| `fault`             | команда отвергнута, потому что `STATE = FAULT`     |
| `line-too-long`     | строка превысила 127 символов                      |
| `no-device`         | DS18B20 не отвечает presence-pulse'ом              |
| `bad-crc`           | CRC scratchpad'а DS18B20 не сошёлся                |
| `bad-value`         | scratchpad полностью 0xFF (питание/проводка) — на пути `TEMP READ` |
| `verify-failed`     | `TEMP CONFIG` записал EEPROM датчика, но verify прочитал не то значение |
| `not-implemented`   | команда зарегистрирована, но логики ещё нет (`MOVETO`/`HOME`) |

## 8. Асинхронные события

Когда состояние меняется не как прямой ответ на команду — MCU шлёт событие:

```
!STATE <BOOT|IDLE|MOVING|FAULT>
!FAULT <reason>
!DONE  <what>
```

- `!STATE` — каждое изменение `app_state_t` (включая первое после ребута).
- `!FAULT` — переход в `FAULT` (например, TX DMA TE), `<reason>` — короткий kebab-id.
- `!DONE` — завершение длительной операции (например, `!DONE MOVE`).

Событий много не будет; парсер хоста должен принять любые `!<TAG> [args]\r\n`
и логировать неизвестные теги.

## 9. Сценарий подключения хоста

1. Открыть COM-порт `115200 8N1`.
2. Ничего не предполагать о состоянии MCU — он мог уже работать.
3. Отправить `PING\r\n` и считать корректным ответом `+OK PING uptime=…\r\n`,
   полученный за ≤200 мс. До этого — игнорировать всё, что в буфере (мусор
   от reset/частичная строка).
4. Опционально `VER` для проверки совместимости.
5. Включить нужные потоки независимо: `MOTOR ON`, `HALL ON`, `TEMP ON`. Для
   каждого — свой `RATE`.
6. По окончании сессии — выключить (`MOTOR OFF`, `HALL OFF`, `TEMP OFF`).

## 10. Парсер на стороне хоста (PySide6)

Минимальный шаблон под `QSerialPort`:

```python
from PySide6.QtSerialPort import QSerialPort
from PySide6.QtCore import QIODevice

port = QSerialPort("COM5")
port.setBaudRate(QSerialPort.Baud115200)
port.open(QIODevice.ReadWrite)

def on_ready_read():
    while port.canReadLine():
        line = bytes(port.readLine()).decode("ascii", errors="replace").rstrip("\r\n")
        if not line:
            continue
        if line.startswith("$M,"):
            _, ts, pos, sp, tgt, en, dr = (s.strip() for s in line.split(","))
            on_motor(int(ts), int(pos), int(sp), int(tgt), int(en), int(dr))
        elif line.startswith("$T18,"):
            _, ts, t = (s.strip() for s in line.split(","))
            on_temp(int(ts), float(t))
        elif line.startswith("$H,"):
            _, ts, raw, c = (s.strip() for s in line.split(","))
            on_hall(int(ts), int(raw), int(c))
        elif line.startswith("+OK"):
            on_ok(line[4:])
        elif line.startswith("-ERR"):
            on_err(line[5:])
        elif line.startswith("!"):
            on_event(line[1:])
        elif line.startswith("#"):
            pass    # comment / banner
        else:
            log.warning("unparsed: %r", line)

port.readyRead.connect(on_ready_read)
port.write(b"PING\r\n")
```

Строки отправляются всегда с `\r\n`. Для отправки команд удобно завести
`def send(cmd: str) -> None: port.write(cmd.encode("ascii") + b"\r\n")`.

## 11. Ограничения и пропускная способность

- 115200 baud ≈ 11.5 КБ/с; одна строка `$H` ≈ 25–30 байт → теоретический потолок
  ~380 Гц на одну подписку. На практике все четыре потока вместе на дефолтных
  частотах (`MOTOR 10` + `HALL 10` + `PROBE 10` + `TEMP 1` = 31 строка/с)
  занимают ≈ 1 КБ/с — ~9% канала. Запас на команды и события — большой.
- `PROBE DUMP` — отдельный случай: ~32 строки × ~400 байт = 12.8 КБ ≈ 1.1 секунды
  занятого канала. На время дампа другие стримы пропускают тики, но не теряют
  порядок строк.
- RX-кольцо 256 байт; `task_protocol` опрашивает раз в 2 мс → за этот интервал
  при 115200 успевает прийти ≤24 байта. Переполнения считаются в
  `uart2_rx_overflows()` — для алертов на UI.
- Длина строки команды строго < 128 байт (`SHELL_LINE_MAX = 128`).
- Стеки FreeRTOS-задач: `protocol = 2048` (длинные `vsnprintf` в `PROBE DUMP`),
  `motor/temp/hall/probe = 1024`, `diag/wdg = 256`. Полная таблица —
  в [tasks.md](tasks.md).

## 12. Расширение

Добавление новой команды — три шага:

1. Реализовать обработчик в [shell.c](../firmware/src/middleware/shell/src/shell.c)
   по сигнатуре `static void cmd_xxx(int argc, char *argv[])`.
2. Зарегистрировать в таблице `s_cmds[]`.
3. Описать команду здесь, в `docs/cli.md`, и в шапке [shell.h](../firmware/src/middleware/shell/inc/shell.h).

Если команда нужна и в бинарном протоколе — сначала добавить её в
`shared/protocol/protocol.yaml`, потом завернуть текстовую обёртку.
